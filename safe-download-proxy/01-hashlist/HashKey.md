## 코드 읽기 전 생각
" HashKey " 만 봤을 때 드는 생각
=> 해시 키를 찾는 파일
=> 해시 키의 역할이 중요하게 다뤄진다.
==> 해시 값과 해시 종류를 묶은 복합키(hash_type, hash_value)였다. 블랙/화이트리스트에서 쓴다.

- 이름만 보면 어떤 역할을 하는 클래스일까?
=> 해시 키를 부여하는 곳
==> 키를 부여하는 곳이 아니라, 검증을 통과한 해시 값만 담아서 키로 쓰게 하는 클래스

- 값 객체(Value Object)는 뭐고, 일반 객체와 뭐가 다를까?
=> 값 객체는 식별자 없이 값만으로 의미를 가지는 것이다.
일반 객체와의 차이점은 식별자의 유무와 상태 변경 가능성이다.
값 객체의 경우 불변성을 가지지만 일반 객체의 경우 가변성을 가진다.

- 해시 값이 잘못됐는지 검사한다면 어디에서 할까? (Day 2의 InvalidHashException과 연결해서)
=> 객체를 만들 때 검사해서 틀리면 InvalidHashException을 던질 것 같다.

- HashType(해시 종류)과는 어떻게 이어질 것 같나?
=> 해시 값과 종류를 같이 들고 있을 것 같다.

## 코드 읽은 후 생각

**Q. 클래스 모양은? (class, record 등) 필드는 무엇을 가지고 있나?**

A.인스턴스 필드와 static 필드를 가지고 있다.

**Q. 객체는 어떻게 만드나? (생성자, 정적 메서드 등) 외부에서 마음대로 만들 수 있나?**

A. 생성자가 private이라 밖에서 new로 만들 수 없다. 
정적 메서드 sha256(String raw)로만 만든다. 
protected 기본 생성자는 JPA가 DB에서 읽을 때 쓰는 용도이다.

**Q. 해시 값 검증은 어디에서 어떻게 하나? (InvalidHashException은 언제 던지나)**

A. sha256() 안에서 검증한다.
- raw가 null이면 InvalidHashException("SHA-256 값이 비어 있습니다.")
- 공백 제거와 소문자 변환 후 64자리 16진수 정규식에 안 맞으면 InvalidHashException("SHA-256은 64자리 16진수여야 합니다.")
- 생성자가 private이라 sha256()을 거치지 않고는 만들 수 없어서 검증을 우회할 수 없다.

**Q. 값을 변환하거나 정리(예: 대소문자)하는 부분이 있나? 왜 필요할까?**

A.public static HashKey sha256(String raw) 여기서 소문자로 변환하는 부분이 존재한다.
왜 필요한가? 대문자/소문자만 다른 같은 해시가 서로 다른 값으로 취급되는 걸 막기 위함이다.    

**Q. 같은 해시인지 비교는 어떻게 하나? (equals, hashCode)**

A. 값으로 판별한다. (메모리 위치X)

**Q. HashType은 이 클래스와 어떤 관계인가?**

A. HashKey가 hashType 필드로 해시 종류를 들고 있다. (hash_type, hash_value)가 합쳐진 복합키다. 

**Q. 이 클래스를 어디에서 쓰는지는 이 파일로 알 수 있나?**

A. 알 수 없다.
